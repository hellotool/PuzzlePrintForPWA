# 功能规划

本文是基于代码现状与产品定位的功能盘点与规划，仅供开发参考。
产品定位：把多张转账/订单等凭证截图以网格拼图方式批量打印到纸上，便于裁切、归档、报销。

## 1. 现状基线

已具备：批量选图（文件选择器）、网格行列布局、纸张尺寸与方向、内容边距（预设 + 自定义）、
裁切网格线、灰度/彩色预览、浏览器打印、PWA 离线、Tauri 桌面壳、中英双语框架。

## 2. 产品原则（已确认）

- **打开即空、不留痕迹**：每次进入都是初始状态。不做 IndexedDB 会话草稿恢复——
  凭证截图含姓名、卡号、交易明细，"本机无任何留存"是隐私卖点，写进 README。
- **配置放 sessionStorage，图片什么都不放**：
   - 布局/边距等非敏感配置写入 sessionStorage：刷新可恢复，关标签页即消失，不写磁盘。
   - 图片不做任何持久化。理由：sessionStorage 只存字符串，base64 体积 +33% 且主线程编解码卡顿；
     每源约 5MB 上限，两三张截图即超；浏览器"会话恢复"会把 sessionStorage 序列化到磁盘，
     等于悄悄留存敏感截图，违背无痕原则。
   - 若未来确需"崩溃不丢图"，形态是默认关闭的显式开关 + IndexedDB，并在 UI 明示本机留存截图。
- 丢图事故的缓解方式是**把导入做快**（整文件夹拖入、粘贴多张、Tauri 记住上次目录），
  而不是持久化。

## 3. P0 —— 直接命中当前痛点

| 功能 | 现状缺口 | 说明 |
| --- | --- | --- |
| 粘贴/拖拽导入 | 未支持，且 `makeDisableDefaultDropListener` 主动禁用了拖拽 | 凭证图多来自微信/QQ，Ctrl+V 粘贴截图是最高频入口；按形态（预览图 vs 凭证页）决定是否拦截默认行为 |
| PDF 导出 | 只能借浏览器打印对话框"另存 PDF" | 发打印店、归档、报销上传都需要 PDF 文件；也是兼容性表中"方向/纸张错误"的旁路方案 |
| 图片列表管理 | `ImagesStore` 只有 add/clear | 需要单张删除、拖拽调序、重复添加控制 |
| 页码/序号 | 预览与打印均无编号能力 | "第 N 笔转账"，编号即证据链；序号样式随网格排布 |

## 4. P1 —— 体验差距项

- **配置持久化（sessionStorage 层）**：`createConfigStore` 初始化读种子值，`createEffect` 写回；
  附"恢复默认"入口。见第 2 节原则。
- **自动布局**：按图片宽高比自动推荐行列数与方向，一键整理（做完可降低"记住配置"的价值感）。
- **适配模式**：格内图片 contain / cover / 白底填充可选。
- **单图编辑**：旋转、裁剪（走 PDF 导出链路可做完整；浏览器打印链路受限）。
- **裁切标记增强**：角线（crop marks）、切线颜色/粗细、页边距留白开关。
- **页眉/页脚**：标题（案件名、报销单号）、日期、文件名。
- **Tauri 原生打印**：绕过 webview 打印对话框，静默打印、指定打印机/份数/双面。

## 5. P2 —— 场景增值项

- 凭证模板：微信/支付宝转账、订单详情等常见截图的一键预设（自动边距 + 编号格式）。
- 隐私打码：手机号/卡号/姓名模糊。先做手动区域涂抹，自动识别成本高后置。
- 拼接长图导出：同套布局输出单张长图，用于线上发送。
- 每页不同张数、混合尺寸。
- 移动端相机导入、HEIC/WebP 兼容。
- 深色模式 UI（`usePreferredDarkMode` 已存在但目前只服务预览）。
- 多语言补全：当前 UI 文案全部硬编码中文，`en` 词典只有应用名。这是架构文档迁移清单
  第 5 步（词典下沉）的前提工作，需先补译再下沉。

## 6. 排期主线

导入（粘贴 + 列表管理）→ 输出（PDF + 页码）→ 会话内配置保持 → 自动化（自动布局/模板）。

前两组做完可显著减少 README 兼容性表的痛点面，并具备摘除"实验性项目"标签的条件。
